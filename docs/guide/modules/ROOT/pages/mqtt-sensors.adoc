= MQTT sensors

A sensor node reports readings to the hub over MQTT: the node publishes each reading to a topic,
an MQTT broker relays it, and the hub (subscribed to that broker) stores the reading against the
matching device.

[plantuml,mqtt-sensors,svg]
----
@startuml
node "Sensor node" as snode
node "MQTT broker" as broker
node "SmartHome hub" as hub
snode --> broker : publish\nhome/<node>/<sensor>
hub --> broker : subscribe\nhome/+/+
@enduml
----

== Run a broker

The hub subscribes to one MQTT broker. Any broker works; Mosquitto is a common choice and runs on
any always-on host on the LAN (a small board, a NAS, or a server). Install it, have it listen on the
LAN so the hub can reach it, and require authentication for anything beyond a trusted network.

== Point the hub at the broker

The broker is connected from the web UI, not from static config: open *Configuration* (the gear
icon in the top-right), go to the *MQTT* tab, enter the broker's host under *Connect an MQTT
broker*, and connect. The hub remembers the connection and re-establishes it on restart. If the
broker requires authentication, supply the credentials as `SMARTHOME_MQTT_USERNAME` /
`SMARTHOME_MQTT_PASSWORD` environment variables.

The hub subscribes to `home/+/+`.

== Add a sensor

There is nothing to register by hand. A node appears on its own the first time it publishes: the hub
creates the device from the node id in the topic and adds each recognized measurement as a sensor.

Publish readings from the node to `home/<node-id>/<sensor-key>`, with the value as the payload. Any
MQTT client can do it; for example, to test:

[source,bash]
----
mosquitto_pub -h <broker-host> -t home/living-room/temperature -m 21.6
----

The node id and sensor key are the last two topic segments, so this creates a `living-room` node
with a `temperature` sensor. Only recognized measurement keys (temperature, humidity, pressure, CO2,
air quality, power, and so on) become sensors; an unknown key is ignored. A real node runs a small
program that reads its sensors and publishes on an interval; a working reference (a Raspberry Pi
reading a couple of I²C sensors) is in `infrastructure/sensor-node/`.

The hub stores each reading against the matching sensor, and the dashboard shows it with a chart of
the sensor's recent history.

== Broker and node on one host (optional)

The broker and a sensor node need not be separate machines: one host can run the broker and also
publish its own sensors. Any arrangement of a broker and nodes on the LAN works.
