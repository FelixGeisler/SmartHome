= Adding devices

A device is registered once; from then on the dashboard presents the controls and readings its
capabilities call for.

A device reaches the hub one of two ways:

* *Through a bridge*: A broker or hub fronts many devices over one connection;
  you connect the hub to the bridge once, and it brings in the devices behind it.
* *Directly*: The device exposes its own network API, so the hub talks to it directly.

Devices and integrations are set up on the *Configuration* page, opened from the gear icon in the
top-right; each integration has its own tab.

== Devices behind a bridge

Connect the hub to the bridge once; how its devices appear then depends on what the bridge can do.

[#hue-lights]
=== A Hue bridge

The bridge reports its own lights, so you pick them rather than entering each by hand.

. Use *Pair a Hue bridge* and enter the bridge's host (its IP address or hostname).
. Press the round link button on the bridge, then start pairing; the bridge only hands out an
  access key for a few seconds after the button is pressed.
. Once paired, the hub lists the bridge's lights. Select the ones to add; each arrives with the
  capabilities the bridge reports, and the dashboard shows the matching controls: an on/off
  toggle, and where the light supports it, brightness, color, and color temperature.

The access key the bridge returns is connection state, never committed to source.

=== A Homematic CCU

The CCU fronts a whole house of Homematic devices, so you connect it once and pick channels.

. Use *Connect a Homematic CCU* and enter its host and your CCU web credentials.
. Once connected, the hub lists the CCU's channels. Select the ones to add; switches and dimmers
  arrive with their controls, climate and contact channels as sensors that report readings.

The CCU password is connection state, never committed to source.

=== An MQTT broker

A broker can't list what publishes through it, and sensor nodes aren't added by hand: connect the
hub to the broker, and each node appears on its own the first time it publishes. The hub creates the
device from the node id in the topic and adds each recognized measurement as a sensor. See
xref:mqtt-sensors.adoc[MQTT sensors] for the broker setup and topic conventions.

== Direct devices

A Shelly Plug is reached straight over HTTP, with no bridge. Use *Add device*, enter a name and its
host, and register it.

A Solakon inverter is reached over Modbus TCP. Use *Connect a Solakon inverter* and enter its host,
port, and unit id; its power and energy readings then flow in. If the inverter is not on your
network (for example, no Ethernet drop nearby), you can bridge it with a Raspberry Pi; see the
`infrastructure/solakon-relay/` reference.

== From the API

Every registration the dashboard performs is also a plain REST call. The exact request shapes are documented live and always in sync at the hub's
API reference, `/swagger-ui.html` (see xref:getting-started.adoc[Getting started]).
