= 7. Deployment View

The hub is a single self-contained Spring Boot JAR, with an embedded database, that serves the
dashboard SPA and the REST API (xref:adr/0001-serve-the-spa-from-the-spring-boot-jar.adoc[ADR 1]). It
reaches devices and gateways over the home LAN, records reading history in its own database, and
calls the Claude API for the assistant.

[plantuml,deployment,svg]
----
@startuml
skinparam componentStyle rectangle

node "Browser" {
  artifact "dashboard SPA" as spa
}
node "Host" {
  artifact "smarthome.jar" as app
  database "embedded DB" as db
}
node "Home LAN\ndevices & gateways" as lan
cloud "Claude API" as claude

spa --> app : HTTP, same origin
app --> db : JPA
app <--> lan : LAN protocols\n(HTTP, MQTT, Modbus, JSON-RPC)
app --> claude : HTTPS (tool-use)
@enduml
----

[cols="1,3",options="header"]
|===
| Node / channel | Role
| Browser | Loads the SPA from the jar over the same origin, so no CORS
| `smarthome.jar` (Host) | The whole hub in one process: serves the SPA at `/` and the API under `/api`
| embedded DB (Host) | The hub's on-disk database on the same host, written over JPA (ADR 7); holds the device registry and sensor reading history
| Home LAN devices & gateways | Devices and bridges the hub reaches over the LAN: Shelly and Hue over HTTP, sensor nodes over MQTT (via a broker, see the xref:guide::mqtt-sensors.adoc[MQTT sensors guide]), a Solakon inverter over Modbus TCP, and a Homematic CCU over JSON-RPC
| Claude API | External cloud service the assistant calls over HTTPS for tool-use turns (ADR 9)
|===
