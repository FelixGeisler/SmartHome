= 7. Deployment View

The hub is a single Spring Boot JAR that serves the dashboard SPA and the REST API
(xref:adr/0001-serve-the-spa-from-the-spring-boot-jar.adoc[ADR 1]). It commands devices over the LAN,
ingests telemetry from an MQTT broker and a Modbus inverter, records reading history in its own
database, and calls the Claude API for the assistant.

[plantuml,deployment,svg]
----
@startuml
skinparam componentStyle rectangle
node "Browser" {
  artifact "dashboard SPA" as spa
}
node "Host" {
  artifact "smarthome.jar" as app
  database "Database\n(registry + history)" as db
}
node "Command device\n(e.g. Shelly / Hue)" as plug
node "Sensor node" as sensor
node "MQTT broker" as broker
node "Solar inverter\n(e.g. Solakon)" as inverter
cloud "Anthropic Claude API" as claude

app --> db : JPA
spa --> app : HTTP same origin\n(SPA + /api)
app --> plug : HTTP (LAN)
app --> inverter : Modbus TCP\n(LAN, poll)
sensor --> broker : publish
app --> broker : subscribe\n(MQTT, LAN)
app --> claude : HTTPS (tool-use)
@enduml
----

[cols="1,3",options="header"]
|===
| Node / channel | Role
| `smarthome.jar` (Host) | Serves the SPA at `/` and the API under `/api`, and persists the registry and reading history to a database
| Browser | Loads the SPA from the JAR over the same origin, so no CORS
| Command device | Reached directly over the LAN, addressed by host (e.g. a Shelly plug over HTTP)
| MQTT broker | Carries sensor telemetry; the hub subscribes to `home/+/+`
| Sensor node | Publishes readings to `home/<device>/<sensor>`; setup is in the xref:guide::mqtt-sensors.adoc[MQTT sensors guide]
| Solar inverter | Reached over the LAN via Modbus TCP; the hub polls it for its telemetry
| Anthropic Claude API | External service the AI assistant reaches over HTTPS for tool-use turns
|===
