= ADR 2: Capability-based device state

== Status
Accepted

== Context
Devices vary: some switch, some dim or change color, some only report readings. Deriving behavior from a fixed device category can't tell two same-category devices with different abilities apart and makes every new behavior a schema change.

== Decision
A device declares a set of capabilities (on/off, brightness, color, color temperature), each a typed contract that owns the neutral attributes it reports and the commands it accepts. Capabilities compose and are not inherited from a category. The set is fixed when the device is registered or provisioned, and stored on the device. A command using a capability the device doesn't have is rejected. Category is used only for grouping and icons, never to gate commands. Sensor readings are separate measurement channels, not capabilities.

== Consequences
Adding a device kind means listing its capabilities. Adding a behavior means one capability plus its contract. The capability set is the source of truth for the command gate, adapters, and dashboard controls. State is stored as strings; the contract enforces its shape.
