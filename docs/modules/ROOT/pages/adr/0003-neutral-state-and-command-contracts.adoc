= ADR 3: Neutral state and command contracts

== Status
Accepted

== Context
For commands and state to work across ecosystems and be shared by the command gate, adapters, and dashboard, every behavior needs one neutral vocabulary with defined types, units, and ranges. Otherwise each adapter and UI invents its own encoding.

== Decision
A fixed set of neutral attribute keys defines both state values and command arguments; each key owns its type, unit, range, and parse/validate logic.

[cols="1,1,2",options="header"]
|===
| Attribute | Encoding | Rule
| On/off | boolean | Setting brightness on an off device turns it on
| Brightness | percentage, 1-100 | Zero is not the off state
| Color | CIE xy chromaticity | A device is in one color mode at a time
| Color temperature | absolute Kelvin | Setting color and color temperature together is rejected
|===

The active color mode follows whichever was set last. Declared ranges are a sanity bound; a device's real limits are applied inside its adapter.

== Consequences
[cols="1,1",options="header"]
|===
| Gain | Cost
| Shape and validity are enforced once, in the contract | Every adapter translates neutral to native and back
| A scene written in neutral keys replays on any ecosystem | A device feature with no neutral key stays invisible until the vocabulary grows
|===
