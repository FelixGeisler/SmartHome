= 5. Building Block View

The hub is a single Spring Boot backend built from feature packages, with a bundled React SPA as its browser client.
Level 1 keeps to the essentials: the `device` core, the `integration` seam that plugs in device ecosystems, and the supporting `services` (automation, assistant, telemetry, realtime) built on the core. The hub's external neighbors are in the xref:03-context-and-scope.adoc[context view].
Level 2 opens up `device`, `integration`, and `telemetry` for their internal structure.

== Level 1

[plantuml,building-blocks,svg]
----
@startuml
skinparam componentStyle rectangle

[frontend] as fe #line.dashed

rectangle "SmartHome Hub" {
  [device core] as device
  [integration] as integration
  [services] as services
}

node "Device ecosystems" as world

fe --> device : REST
services --> fe : live updates
device <--> integration
services --> device
integration --> world : device I/O
@enduml
----

[cols="1,4",options="header"]
|===
| Block | Responsibility
| `frontend` | The React SPA dashboard: register, control, chart, and group devices, plus the AI chat. It sees only the REST contract, never the domain model.
| `device` core | The device domain: the neutral model and capabilities (ADR 3), control logic and persistence, and the organizing layers (rooms, floors, dashboard layout). Its parts are its <<wb-device,whitebox>>.
| `integration` | The `DeviceAdapter` port and the registry that routes to it, one sub-package per ecosystem (ADR 4). Its parts are its <<wb-integration,whitebox>>.
| `services` | Built on the core: automations (ADR 12), the AI assistant (ADR 9), telemetry history (ADR 14), and live dashboard updates over SSE (ADR 11).
|===

== Level 2

[#wb-device]
=== The `device` core

[plantuml,bb-device,svg]
----
@startuml
skinparam componentStyle rectangle

package "device" {
  [DeviceController] as ctl
  [DeviceService] as svc
  [DeviceRepository] as repo
  [Device (model)] as model
}
[capability] as cap
interface "DeviceAdapter\n(port)" as port
[telemetry]
[realtime]
database "Database" as db

ctl --> svc : register / list / command
svc --> model : mutate state
svc --> repo : load / save
repo --> db : JPA
svc ..> cap : validate against\nneutral vocabulary
svc --> port : route command
svc --> [telemetry] : reading recorded
svc ..> [realtime] : device changed / removed
@enduml
----

[cols="1,3",options="header"]
|===
| Part | Responsibility
| `DeviceController` | The REST surface: register, list, toggle, and command devices, and read their sensors.
| `DeviceService` | The core logic: resolves capabilities, routes commands through the adapter port, records readings, and emits change and reading events.
| `DeviceRepository` | Spring Data JPA persistence of the device aggregate.
| `Device` (model) | The device aggregate: its type, capabilities, state, and sensors.
|===

[#wb-integration]
=== The `integration` package

[plantuml,bb-integration,svg]
----
@startuml
skinparam componentStyle rectangle

[device core] as device
package "integration" {
  [DeviceAdapterRegistry] as registry
  interface "DeviceAdapter\n(port)" as port
  [command adapters] as adapters
  [telemetry sources] as sources
}
node "Device ecosystems" as world

device --> registry : command
registry --> adapters : route by type
adapters ..|> port
adapters --> world : vendor API
world --> sources : readings
sources --> device : record readings
@enduml
----

[cols="1,3",options="header"]
|===
| Part | Responsibility
| `DeviceAdapter` (port) | The neutral outbound port a command device is reached through.
| `DeviceAdapterRegistry` | Resolves the adapter for a device by its adapter type.
| Command adapters (`hue`, `shelly`, `homematic`) | Implement the port, translating a neutral command into the vendor's API.
| Telemetry sources (`mqtt`, `solakon`, and the `shelly` and `homematic` pollers) | Feed readings straight into the core: MQTT by subscribing to a broker, the others by polling a device or gateway. An ecosystem can do both: Shelly and Homematic command and report.
|===

[#wb-telemetry]
=== The `telemetry` side

[plantuml,bb-telemetry,svg]
----
@startuml
skinparam componentStyle rectangle

[device core] as device
package "telemetry" {
  [Reading recorder] as rec
  [History service] as hist
  [History API] as histapi
  [Retention job] as ret
}
[frontend] #line.dashed
[assistant]
database "Database" as db

device --> rec : reading recorded
rec --> db : append reading
histapi --> hist : query
hist --> db : read history
ret --> db : prune old readings
[frontend] --> histapi : history (/api)
[assistant] ..> hist : tool-use
@enduml
----

[cols="1,3",options="header"]
|===
| Part | Responsibility
| `SensorReadingRecorder` | Listens for reading events and appends each numeric reading to the database.
| `TelemetryHistoryService` | Reads a sensor's recent history back from the database.
| `TelemetryHistoryController` | Serves that history over the REST API.
| `TelemetryRetentionJob` | Prunes readings past the retention window to bound the table.
|===
